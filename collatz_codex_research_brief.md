# Codex Research Brief: Adaptive Affine Certificates for the Collatz Conjecture

## Codexへの最初の指示

この仕様を最後まで読んでから、まず **Phase 1 と Phase 2だけ**を実装してください。
数学的証明を主張してはいけません。すべての計算は厳密整数演算で行い、再現コマンド、テスト結果、出力ファイルの SHA-256 を残してください。

目標は計算上限を伸ばすことではなく、正整数全体を覆いうる「有限かつ独立検証可能な再帰証明書」の探索基盤を作ることです。
探索器と検証器は別実装にし、共通の判定ロジックをコピーしないでください。

---

## 1. Mathematical objective

Use the shortcut Collatz map

\[
T(n)=
\begin{cases}
n/2,&n\equiv0\pmod2,\\
(3n+1)/2,&n\equiv1\pmod2.
\end{cases}
\]

A universal proof follows if, for every integer \(n>1\), one can certify either:

1. some iterate satisfies \(T^j(n)<n\); or
2. its orbit merges into the orbit of a smaller positive integer whose convergence is already covered by a well-founded certificate.

The project searches for a finite recursive certificate establishing this statement for all \(n>1\).

This is **not** a request to verify a larger finite interval.

---

## 2. Exact affine-cylinder representation

A node is

```text
Node(k, r, y, q)
```

with the semantics

\[
n=r+2^k t,\qquad
T^k(n)=y+3^q t
\]

for every integer \(t\ge t_{\min}\), where \(0\le r<2^k\), \(q\) is the number of odd shortcut steps in the fixed parity prefix, and

\[
t_{\min}=\max\left(0,\left\lceil\frac{2-r}{2^k}\right\rceil\right).
\]

The root represents all \(n\ge2\).

Store the parity word too, but regard it as derived/debug data rather than trusted certificate data.

### Exact split rule

Let \(A=3^q\), \(B=2^k\). Split \(t=2u+\varepsilon\), \(\varepsilon\in\{0,1\}\).

\[
r'=r+\varepsilon B,\qquad z=y+\varepsilon A,\qquad p=z\bmod2.
\]

If \(p=0\),

\[
y'=z/2,\qquad q'=q.
\]

If \(p=1\),

\[
y'=(3z+1)/2,\qquad q'=q+1.
\]

The child is

```text
Node(k+1, r', y', q')
```

and represents \(n=r'+2^{k+1}u\).

The independent checker must verify every split algebraically.

## 3. Certificate rule language

Implement a JSON certificate format with the following initial rule types.

### 3.1 SPLIT

A parent node is exactly covered by its two children obtained from the split rule.

### 3.2 DESCENT

For a node,

\[
T^k(n)-n=(y-r)+(3^q-2^k)t.
\]

The rule is valid if this is strictly negative for every \(t\ge t_{\min}\).

For a negative slope, it suffices to test \(t=t_{\min}\).

### 3.3 FINITE_TAIL

If \(2^k>3^q\), then only finitely many parameters can fail descent.

Let

\[
H=\left\lfloor\frac{y-r}{2^k-3^q}\right\rfloor.
\]

All \(t>H\) descend at step \(k\). The rule reduces the node to the explicit integers corresponding to

\[
t_{\min}\le t\le H.
\]

Handle \(H<t_{\min}\) as immediate descent.

### 3.4 DIRECT

For one explicit integer \(n\), provide a finite orbit prefix ending at a value \(<n\) or at \(1\).
The checker recomputes the orbit; the certificate must not contain trusted intermediate arithmetic.

### 3.5 MERGE

A symbolic merge rule may be added only after Phase 1 is stable.

It must provide:

- source affine family \(n(t)\);
- a smaller affine family \(m(u)\);
- fixed parity words for both paths;
- an affine relation \(u=\alpha t+\beta\);
- an exact identity
  \[
  T^a(n(t))=T^b(m(u));
  \]
- domain integrality and positivity;
- the strict inequality \(m(u)<n(t)\);
- a dependency edge to a strictly lower certificate rank.

The checker verifies the affine identities and a well-founded dependency DAG.

Do not accept an empirical path merge.

## 4. Repeated-block macro to investigate

For a parity block \(w\) of length \(L\), with \(q_w\) odd steps, write

\[
W(x)=\frac{P x+B_w}{Q},\qquad
P=3^{q_w},\quad Q=2^L.
\]

An exact identity is

\[
(Q-P)W^m(x)-B_w
=
\left(\frac{P}{Q}\right)^m\bigl((Q-P)x-B_w\bigr).
\]

Hence, if \(W^i(x)\) is integral for \(0\le i\le m\),

\[
Q^m\mid (Q-P)x-B_w.
\]

This divisibility explains arbitrarily long shadows of negative or rational cycles.

In Phase 2, mine surviving branches for repeated blocks, but do **not** assume that a finite dictionary of periodic shadows covers all branches.

Record for each candidate block:

- \(L,q_w,P,Q,B_w\);
- reduced rational fixed point \(B_w/(Q-P)\);
- longest repetition count;
- \(v_2((Q-P)r-B_w)\);
- exit parity word and exact affine map after exit.

A future MACRO rule must be parametric in the repetition count and independently checkable.

## 5. Phase 1: baseline exact engine

Create:

```text
src/search.py
src/model.py
verifier/verify_certificate.py
tests/
README.md
```

Requirements:

1. Python 3.12 or later.
2. Only arbitrary-precision integers and `fractions.Fraction`; no floating point in any proof decision.
3. Deterministic traversal and stable JSON output.
4. Generate the raw recursive tree to at least depth 26.
5. Prune with DESCENT and FINITE_TAIL.
6. Directly verify every finite exception generated by FINITE_TAIL.
7. Compare all represented integers below \(2^{24}\) against direct Collatz iteration.
8. The verifier must reconstruct all arithmetic from the JSON certificate.
9. Add property-based tests for the affine-node semantics and split rule.
10. Emit node counts by depth and certificate-rule counts.

Expected sanity-check survivor counts for the simplest DESCENT-only implementation are:

```text
depth 10: 64
depth 15: 1295
depth 20: 27328
depth 22: 93222
```

These are sanity checks, not axioms. If they disagree, diagnose rather than forcing the output.

## 6. Phase 2: obstruction mining

For surviving branches through at least depth 26, produce:

```text
artifacts/survivor_stats.csv
artifacts/repeated_blocks.json
artifacts/canonical_signatures.json
artifacts/obstruction_report.md
```

For each branch record:

- parity prefix;
- every prefix coefficient comparison \(3^{q_i}\) versus \(2^i\);
- affine parameters \((r,y,q,k)\);
- \(T^k(n)-n\) slope and intercept;
- shortest exact period of the word;
- best repeated-prefix and repeated-suffix blocks of length at most 16;
- rational fixed point of each repeated candidate block;
- reduced numerator/denominator and their bit lengths;
- whether an earlier uniform descent occurred;
- whether a generic smaller-preimage/path-merge pattern is found.

Cluster branches only by exact discrete signatures. Numerical embeddings may be used for visualization but never for proof decisions.

Explicitly test the hypothesis:

> A finite dictionary of short periodic/rational shadows explains all surviving branches.

The expected outcome may be negative. Return exact counterexample words and growth rates if the dictionary fails.

## 7. Phase 3: CEGAR loop (do not implement yet)

Future loop:

1. Generate unresolved exact cylinders.
2. Mine a proposed recursive rule or parametric macro.
3. Send it to the independent checker.
4. On failure, retain the smallest exact counterexample cylinder.
5. Refine the rule language, not merely the search depth.
6. Continue until either:
   - a finite well-founded universal certificate is obtained; or
   - a mathematically explicit infinite obstruction family is isolated.

The second outcome is scientifically useful and must be reported honestly.

---

## 8. Required no-go tests

The implementation must include adversarial families that defeat naive local methods:

\[
n=2^m-1,
\]

which shadows the negative fixed point \(-1\), and

\[
n=8^m-5,
\]

which begins with repeated parity block \(110\) and shadows the negative cycle containing \(-5\).

Also include starts:

```text
1, 3, 7, 9, 27, 47, 63, 91, 97, 871, 6171
```

A candidate bounded-state or fixed-horizon ranking rule must be rejected if one of these families violates it for arbitrarily large \(m\).

## 9. Acceptance criteria for Phase 1–2

The delivery is accepted only if it contains:

1. exact source code;
2. an independent verifier;
3. tests and reproducible commands;
4. deterministic artifact files;
5. SHA-256 hashes;
6. a clear distinction among:
   - proved by the checker,
   - observed computationally,
   - conjectured;
7. an obstruction report that includes failed hypotheses;
8. no assertion that the Collatz conjecture has been proved.

At the end, report:

- whether survivor growth is subexponential, exponential, or unresolved over the tested range;
- which exact signatures dominate;
- whether short periodic-shadow macros cover a non-vanishing fraction;
- the smallest survivor not explained by the current macro dictionary;
- the next mathematically meaningful extension to the certificate language.
